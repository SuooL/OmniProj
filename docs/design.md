# 界面约定

产品定义见 [`omniproj-charter.md`](omniproj-charter.md)。本文只写「界面按什么规矩做」，规矩都能在代码里验证。

## 1. 两个界面，没有第三个

| 界面 | 内容 |
|---|---|
| **项目列表** | 一行一个项目：名字、还剩几步、分支、最近提交、16 周活动条。搜索 + 一个可选排序（最近提交 / 名称 / 剩余步骤）。 |
| **项目页** | 项目名 + 一句话说明 + git 事实一行 → 一年提交热图 → **步骤清单** → 折叠区（提交记录与分支图 / 项目设置）。 |

左侧常驻项目栏，切项目一次点击。没有 tab、没有看板、没有同一份数据的第二个视图。

**清单是页面本身**，不藏在任何折叠或标签后面：它是每次打开都要看的东西，折叠区里的是偶尔才查的。

## 2. 排序与信号

- 列表**不排优先级、不算健康分、不算腐坏度**。默认按最近提交时间排，用户可改。
- 不做「需要你决定 / 待审视」这类分组和徽章。工具报告事实，判断留给人。
- 项目栏的小圆点只表示「还有未完成的步骤」，并且总是配一句屏幕阅读器可读的文字。

## 3. 颜色规则（可测）

- 组件只用 `index.css` 顶部定义的 `--op-*` 语义变量，**不出现裸 hex**。
- 颜色永远与可见文字冗余：没有任何信息只靠颜色传达。
- 全部角色在浅色、深色、高对比度、`forced-colors` 四种情况下都有定义。提交热图在 `forced-colors` 下改用边框粗细承载梯度。
- 没有健康分、优先级排名、发光、脉冲、状态动画。

`semantic.test.tsx` 里的源码扫描会对以上几条中的「无裸 hex / 无 `--color-*` / 无 emoji」直接断言，新组件要加进那份清单。

## 4. 清单的交互契约

- 行默认是**只读的一行文字**，点一下才变成输入框。一次渲染五十个 input 会把「看一眼」变成「填表」。
- 键盘模型（Enter / Tab / Shift+Tab / ⌥↑ / ⌥↓ / 空行 Backspace / Esc）的目标全部在 `domain/outline.ts` 里算，不碰 DOM，因此可以单测。
- 缩进、拖动、删除都**带着整棵子树**走。
- 删除一个有子步骤的父步骤会连子步骤一起删——不会把它们悄悄提升到上一层。
- 空行 Backspace 只对叶子生效；有内容挂在下面的步骤必须明确删除。

## 5. 写入契约

- 每次改动都是显式写入，带 `expected_revision` 校验。blur 不会偷偷保存文本以外的东西。
- 写入是**串行的**：连按回车会排队，每一次用上一次返回的 revision。并发发出去会全部撞版本冲突。
- 冲突后强制重新拉取（`staleTime: 0`），不能拿刚刚失败的缓存继续写。
- 失败有明确文案 + 重新加载，不重发。

## 6. 无障碍

- 列表行是一个链接，其 accessible name 复述整行（名字、剩余步数、分支、最近活动），而不只是项目名。
- 热图是 `role="img"` 加一句总结；单元格用原生 `title`，不自造 tooltip 状态。
- 折叠区用原生 `<details>`；行内的「详情」按钮在 hover 时才显形，但键盘聚焦时一定可见。
